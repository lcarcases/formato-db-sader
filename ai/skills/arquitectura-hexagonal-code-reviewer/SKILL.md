## Goal

Revisar y corregir el código de un caso de uso que ha sido implementado siguiendo los principios de la Arquitectura Hexagonal y el Domain Driven Design (DDD).

- Priorizar que el código sea claro y fácil de entender. Por tal razón se debe evitar la escritura de código fancy, que aunque pueda ser más elegante, puede dificultar la comprensión del código.


- Evitar la escritura de código demasiado simplificado, que aunque pueda ser más fácil de entender, puede dificultar la comprensión del código. Es mejor ocupar más líneas de código y escribir código más explícito, que aunque pueda ser más largo, puede facilitar la comprensión del código.

## When to use this skill

Se debe utilizar esta habilidad cuando se desea revisar y corregir el código de un caso de uso que ha sido implementado siguiendo los principios de la Arquitectura Hexagonal y el Domain Driven Design (DDD), asegurando que el código sea claro, fácil de entender y cumpla con los estándares de calidad.
