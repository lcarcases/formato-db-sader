# Data Model: Tipos de Personal

## Domain Layer

### Entity: TipoPersonal

file: `app/Core/Admin/Domain/Entities/TipoPersonal.php`

```php
<?php
declare(strict_types=1);

namespace App\Core\Admin\Domain\Entities;

/**
 * TipoPersonal Domain Entity
 * 
 * Represents a valid personnel type in SADER (Base, Enlace, Confianza, Externo).
 * Aggregate Root: Yes (simple aggregate with no child entities)
 * 
 * Invariants:
 * - nombre MUST NOT be empty
 * - activo MUST be boolean
 * - Only active TipoPersonal (activo=true) can be exposed via API
 */
final readonly class TipoPersonal
{
    public function __construct(
        public int $id,
        public string $nombre,
        public ?string $descripcion,
        public bool $activo
    ) {
        $this->validate();
    }

    private function validate(): void
    {
        if (trim($this->nombre) === '') {
            throw new \InvalidArgumentException('TipoPersonal nombre cannot be empty');
        }
    }

    public function isActive(): bool
    {
        return $this->activo;
    }
}
```

**Validation Rules**:
- `nombre`: Required, non-empty string
- `descripcion`: Optional string (can be null)
- `activo`: Required boolean
- `id`: Required positive integer (auto-generated by DB)

**State Transitions**: None (immutable entity for read-only catalog)

## Infrastructure Layer

### Database Schema

**Table**: `tb_cat_tipo_personal`

**Columns**:
| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| id_nu_tipo_personal | SERIAL | PRIMARY KEY | Auto-increment identifier |
| sn_nombre | VARCHAR(50) | NOT NULL, UNIQUE | Tipo personal name |
| sn_descripcion | TEXT | NULL | Optional description |
| ind_activo | BOOLEAN | NOT NULL DEFAULT true | Indicates if tipo is available |
| created_at | TIMESTAMP | NOT NULL DEFAULT CURRENT_TIMESTAMP | Record creation time |
| updated_at | TIMESTAMP | NOT NULL DEFAULT CURRENT_TIMESTAMP | Record last update time |

**Indexes**:
- `idx_tb_cat_tipo_personal_activo` ON (activo) - For filtering active records
- `idx_tb_cat_tipo_personal_nombre` ON (nombre) - For potential future search

**Initial Data** (via migration):
```sql
INSERT INTO tb_cat_tipo_personal (sn_nombre, sn_descripcion, ind_activo) VALUES
('Base', 'Personal de base', true),
('Enlace', 'Personal de enlace', true),
('Confianza', 'Personal de confianza', true),
('Externo', 'Personal externo', true);
```

### Repository Implementation

**File**: `app/Core/Admin/Infrastructure/Adapters/Out/PostgresSQL/Repositories/TipoPersonalPostgresSQLRepository.php`

**Responsibilities**:
- Execute SQL query to fetch active tipos personal (WHERE activo = true)
- Order by id_nu_tipo_personal ASC (FR-004)
- Transform Eloquent/QueryBuilder results to stdClass objects
- Handle database exceptions (connection failures, timeouts)

**Query**:
```php
SELECT id_nu_tipo_personal, sn_nombre
FROM tb_cat_tipo_personal 
WHERE ind_activo = true 
ORDER BY id_nu_tipo_personal ASC
```

## Validation Strategy

**Domain Layer**: Entity constructor validates nombre is non-empty and activo is boolean.

**Application Layer**: Use case assumes valid data from repository (no additional validation needed for read-only operation).

**Infrastructure Layer**: 
- **Inbound (API)**: No Form Request needed (GET endpoint with no query parameters).
- **Outbound (Database)**: Repository handles database-level constraint violations (unlikely for read operation).

**Error Handling**:
- Database connection failure → 500 Internal Server Error
- Empty result set → 200 OK with empty array
- Invalid data from DB (e.g., null nombre) → Domain entity validation throws exception → Caught in use case → 500 Internal Server Error
